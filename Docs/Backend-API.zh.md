# YamaBili 服务端接口

[English](Backend-API.md) | 中文

这份文档写给想自建服务端的人。官方服务端不开源，这里只描述插件依赖的接口约定。只要遵守这些约定，用什么方式实现都可以。
Bilibili 登录、风控、播放地址获取和 HTTPS 需要你自己处理。

所有请求都发到 `ServerRoot`（例如 `https://example.com/`）。路径固定为 `/`，不同接口只靠查询参数区分。

## 1. 槽位池

世界里存的是编号 URL，每个编号具体指向什么由服务器决定。

- 每个池有两个环：`v`（可播放的视频）和 `q`（列表页、封面图集），每个环有 `r × 10000` 个槽。
- 池由 **(r, z)** 唯一确定。所有请求都可以带：
  - `r`：1–100，不能有前导零，默认 1
  - `z`：`[a-z]{1,5}`，不传表示共享的默认池
  - `m`：r 和 z 的合写形式，必须匹配 `^([1-9]\d{0,2})?([a-z]{1,5})?$` 且不能为空（`m=10ab` 等于 `r=10&z=ab`）。`m` 和 `r`/`z` 同时出现属于非法请求
- 参数非法时返回 `{"error":"bad_pool"}`；如果是视频播放器发来的请求，改为返回 HTTP 400。
- 分配规则：按顺序写入下一个槽，写到末尾后回到开头，覆盖最旧的条目。带去重 key 的条目（同一视频分P、同一查询页）在被覆盖之前一直复用原来的槽。
- 槽表必须持久化：服务重启后，同一个编号的含义不能变。同一实例里的所有玩家就是靠同一个编号保持同步的。
- 槽号超出范围或槽为空时，返回 `{"error":"expired"}`；视频播放器发来的请求返回 404。

## 2. 路由

| 请求 | 返回 |
|---|---|
| `?search=<关键词或视频链接>` | 列表 JSON，每页 20 条；传入视频链接时只返回这一条 |
| `?mid=<UP 主 id 或空间链接>` | 列表 JSON：该 UP 主的投稿 |
| `?fav=<收藏夹链接或 id>` | 列表 JSON：公开收藏夹 |
| `?q=N` | 重放 q 槽 N：返回列表 JSON；如果该槽存的是图集，返回 JPEG |
| `?v=N` | 见第 3 节 |
| `?url=<Bilibili 视频链接>` | 先给这个视频分配一个 v 槽（即 `i` 字段），之后与 `?v=N` 相同 |

前三个接口用作输入框前缀。玩家在 `…?search=` 后面输入内容，VRChat 会按原样发出请求，其中可能有未编码的 UTF-8，`+` 要当作普通字符处理。

## 3. 同一个 `?v=N` 对应两种客户端

- **Udon 下载器**（VRCStringDownloader，User-Agent 含 `UnityWebRequest` 或 `UnityPlayer`）：返回视频 JSON。
- **视频播放器**（其余所有客户端）：302 跳转到可播放的 mp4 流地址，或者直接代理这条流（需要支持 Range）。
- 调试时加上 `&as=json`，可以强制返回 JSON。

## 4. JSON

所有错误都返回 `{"error":"<code>"}`，状态码用 HTTP 200，因为状态码表示错误时 Udon 读不到响应体。

列表：
```json
{"kind":"search|mid|fav","title":"...","page":1,"pages":50,
 "self":21,"prev":-1,"next":19,"img":20,
 "items":[{"i":0,"bv":"BV...","title":"...","owner":"...","dur":"3:25","up":7}]}
```
`i` 是 v 槽；`self`/`prev`/`next`/`img`/`up` 是 q 槽，`-1` 表示没有。重放 `up` 槽得到该 UP 主投稿的第 1 页。

视频：
```json
{"kind":"video","i":0,"bv":"BV...","p":1,"title":"...","part":"","owner":"...",
 "roll":[[12.5,"弹幕"],[13.0,"彩色",16711680]],"top":[...],"bottom":[...],
 "sub":[[1.0,3.2,"字幕"]],
 "pages":[{"i":5,"title":"P1 ...","link":"https://www.bilibili.com/video/BV...?p=1"}],"cur":0}
```
- 弹幕格式为 `[秒, 文本]`，颜色不是白色时加上第三项 `0xRRGGBB`。
- `sub` 的格式为 `[开始秒, 结束秒, 文本]`。
- `pages` 列出所有分P或合集条目，每项各有一个 v 槽；`cur` 是当前条目在其中的下标，没有分P或合集时为 `-1`。

## 5. 封面图集

`img` 槽返回一张 JPEG，宽 160，高 `90 × 20`。图中从上到下依次是列表 20 个条目的封面，每张 160×90，按铺满方式裁切。没有封面的格子留空。

## 6. 其他

- VRChat 要求使用 HTTPS。
- `/healthz` 可以不实现。
- 只提供公开内容，并遵守 Bilibili 的服务条款。
